# HAProxy Studio

Бесплатная самостоятельная веб-панель для существующего HAProxy. Работает на вашем сервере без внешней телеметрии. Лицензия MIT.

## Визуальная публикация

В разделе «Сервисы» доступен мастер HTTP/HTTPS, RDP/RDS через Connection Broker, SSH, всех основных почтовых протоколов, TCP/TLS и баз данных. Поддерживаются сертификаты PEM/CRT/KEY и PFX/P12, перенаправление HTTP → HTTPS, балансировка, проверки доступности и ограничение по IP. [Пошаговая инструкция](docs/services.ru.md).

## Установка

Требования: Linux, Python 3.9+, установленные HAProxy, OpenSSL и системные CA-сертификаты. Для автоматического запуска — systemd. Целевые системы: Debian 12+, Ubuntu 22.04+, CentOS Stream 9, Rocky Linux 9, AlmaLinux 9. Полноценная установка на каждой из них ещё не проверена: текущая проверка выполнена на CentOS и в Debian-контейнере; CI содержит отдельную матрицу дистрибутивов.

```sh
sudo sh scripts/install.sh
sudoedit /etc/haproxy-studio/config.json
sudo systemctl enable --now haproxy-studio
sudo cat /var/lib/haproxy-studio/initial-password
```

Вход: `admin`. По умолчанию панель доступна только локально: `http://127.0.0.1:9130/haproxy-admin/`. Удалённый доступ: SSH-туннель либо HTTPS reverse proxy с соответствующим `public_url`. Установщик не меняет конфигурацию HAProxy, не открывает порты и сохраняет существующие настройки панели.

Начальный режим — наблюдение. Для управления установите `read_only: false`, проверьте пути и команды перезагрузки, затем перезапустите панель. Перед применением изменений выполняются проверка HAProxy, просмотр разницы и резервное копирование. Неудачная перезагрузка запускает восстановление предыдущего файла.

## Docker

```sh
docker compose up -d --build
docker compose exec studio cat /var/lib/haproxy-studio/initial-password
```

Готовый Docker-вариант предназначен для наблюдения за HAProxy хоста: конфигурация монтируется только для чтения, Docker socket не передаётся. Для управления конфигурацией и системной службой используйте нативную установку. Пути томов и runtime socket нужно сверить со своим сервером. SELinux автоматически не отключается.

## Настройки и данные

Все пути, адрес панели, порт, executable HAProxy и команды управления вынесены в JSON-настройки. `haproxy_binary: auto` определяет путь автоматически. Команды задаются массивами аргументов и исполняются без shell. Резервные копии, хеш пароля, начальный пароль и журнал хранятся в `state_dir`, вне исходников.

Смена пароля доступна в разделе **Мой аккаунт** с подтверждением текущего пароля. Администраторы создают, отключают и удаляют аккаунты в разделе **Пользователи**; доступны роли администратора и наблюдателя. При обновлении существующий пароль `admin` сохраняется. [Управление аккаунтами, сертификатами и backend](docs/administration.ru.md).

Если пароль забыт: остановить службу, выполнить `STUDIO_CONFIG=/etc/haproxy-studio/config.json python3 -m haproxy_studio --reset-password` из каталога приложения, затем снова запустить службу. Новый пароль находится в `state_dir/initial-password`. Старые сессии отзываются при перезапуске.

## Исходники и приватные данные

В проекте есть MIT LICENSE, README, SECURITY.md, .gitignore, Dockerfile, Compose и CI. Рабочая конфигурация, аккаунты, пароли, сертификаты и резервные копии хранятся вне исходников. Установщик не отправляет код или рабочие данные на GitHub.

Проверки: `python3 -m unittest discover -s tests -v`. Подробности архитектуры и ограничений — в [README.md](README.md).

## Exchange и общие TLS-порты

В версии 0.3 добавлены группы доменов, маршруты и проверки служб Exchange, перенаправление корня, HTTP-исключения, общие SMTPS/IMAPS/POP3S-порты с SNI и fallback. [Инструкция и ограничения STARTTLS](docs/exchange-sni.ru.md).

В версии 0.5 добавлен шаблон **RDS через Connection Broker**: прямой вход на брокер/redirector и маршрутизация на Session Host по токену msts. [Настройка RDS](docs/rds.ru.md).
