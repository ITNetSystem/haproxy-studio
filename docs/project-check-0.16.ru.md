# Проверка проекта и импорта: 0.16

Проверены импорт и повторное сохранение публикаций, генерация всех типов мастера, изменение общих backend, ACL с AND/OR/отрицаниями, смешанный TLS/passthrough, RDS, сертификаты, учётные записи и роли, конфликты версий файла, резервные копии и откат после неуспешного применения.

## Исправления

1. Одиночная публикация с `slowstart`, stick-table, нестандартными TLS/health-параметрами серверов, наследованием или таймаутом `500ms` могла оставаться ручной, хотя общий пул уже поддерживался. Теперь при невозможности точно преобразовать пул в шаблон импорт сохраняет исходный backend и переносит только доменный маршрут в управление Studio.
2. Импорт TLS зависел от размещения отдельных PEM в каталоге панели. Для сохранённых пулов теперь поддержаны исходные `crt-list`, относительные пути через `crt-base`, каталоги сертификатов и файлы вне хранилища Studio. Их пути и содержимое не переписываются; перед применением весь конфиг проверяется нативным HAProxy. Это не переносит сертификаты на другой сервер и не делает отсутствующий сертификат доступным.
3. Заголовки секций с ведущими пробелами или табуляцией распознаются согласованно с HAProxy.
4. Повреждённые метаданные, содержащие массив вместо объекта, и повторяющиеся идентификаторы сервисов дают понятную ошибку вместо неверной обработки записей.

## Результаты

- 215 тестов Python прошли на Python 3.9.25 с установленным HAProxy. Они включают реальные локальные HTTP/TLS-подключения и проверки сохранения маршрутизации в смешанной схеме с PROXY protocol.
- 47 синтетических конфигураций прошли `haproxy -c` на каждой из веток 2.4, 2.6, 2.8, 3.0, 3.2, 3.3, 3.4: 329 проверок. Версии сборок указаны в README.
- В браузере проверены импорт Exchange, изменение параметров и отдельного ACL пути, подтверждение общего пула, preview/apply и повторное чтение сохранённых настроек. На ширине 1440, 390 и 320 px не обнаружены горизонтальное переполнение, ошибки JavaScript или нарушения axe.
- Проверены синтаксис всех JavaScript-файлов, компиляция Python, синтаксис установочного shell-скрипта и отсутствие ошибок whitespace в diff.
- CI содержит дополнительные проверки на Python 3.12/3.13, нескольких дистрибутивах и сборку Docker. Их наличие в CI не означает, что эти задания уже завершились для опубликованного коммита; статус смотрите в GitHub Actions.

## Что нельзя обещать автоматически

Произвольный конфиг HAProxy не всегда можно без потерь превратить в поля мастера. В частности, динамические map-выражения, неограниченные условия «все домены кроме…», многозначные привязки и несколько defaults, сложные анонимные ACL могут оставаться ручными. Импорт не должен удалять или угадывать такие правила: они сохраняются в конфиге и перечисляются в результате анализа.

Синтаксическая корректность не доказывает доступность внутренних адресов, корректность DNS, доверие клиентов к сертификату, правила firewall и настройки Exchange/RDS. Эти свойства проверяются на целевой инфраструктуре.

`ssl_fc_sni` не даёт доменную маршрутизацию на обычном SMTP/587 без TLS на bind. STARTTLS нельзя исправить заменой одного ACL: требуется общий SMTP-пул/почтовый маршрутизатор либо отдельные IP/порты. Аналогично разбор произвольного фрагмента SMTP payload не равен маршрутизации по домену получателя.

В конфигурациях для HAProxy 2.4 настройка `tune.ssl.capture-buffer-size` может быть неизвестна. Для подготовленных вариантов проверено общее имя `tune.ssl.capture-cipherlist-size`. DH-директивы также зависят от SSL-библиотеки: варианты с AWS-LC проверяйте отдельно либо используйте ECDHE. Studio не меняет эти политики без предварительного просмотра.

Файлы реальной инфраструктуры и подготовленные для неё варианты не входят в публичный репозиторий. Они выдаются отдельно владельцу, со сравнением команд backend, условий и порядка маршрутов, разницей и описанием изменений TLS-политики.
