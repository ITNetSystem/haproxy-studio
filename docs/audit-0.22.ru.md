# Проверка проекта и исправления 0.22

Дата проверки: 27 ноября 2026 года.

## Исправления

- Сопоставление почты с Exchange учитывает актуальные адреса исходных backend, а не устаревшие адреса в модели. Конфликт домена одной организации и IP другой не приводит к автоматическому объединению.
- Удаление Exchange удаляет все принадлежащие ему управляемые почтовые службы даже при пустом списке почты в запросе. Ручные правила не удаляются этим действием.
- Проверяются формат составного запроса и типы почтовых служб. Тип из присланной клиентом подписи не подменяет действительный протокол существующего сервиса.
- Добавлен проверяемый мастер исправления старых SNI-условий на STARTTLS-входах. Узлы DAG не разделяются; одинаковые пулы объединяются, разные назначения требуют явных адресов/портов.
- Сохраняются отдельные таймауты клиента и сервера и явное `log global`. Повторный порт проверки, совпадающий с портом сервера, поддерживается импортом. Другие порты не отбрасываются.
- Docker healthcheck использует настроенные порт, адрес и base_path, обращается напрямую к локальному процессу без внешнего HTTP-прокси.
- CI устанавливает HAProxy и OpenSSL для основного набора тестов и проверяет синтаксис JavaScript. Тесты генератора больше не зависят от случайного наличия HAProxy на runner.

## Проверки

- 275 автоматических тестов: импорт ACL и общих backend, Exchange/DAG, составные операции, RDP/RDS, RD Web, сертификаты, учётные записи, защита самой панели, применение/откат, мониторинг и запуск.
- 54 конфигурации на семи ветках HAProxy: 2.4, 2.6, 2.8, 3.0, 3.2, 3.3, 3.4 — 378 успешных проверок `haproxy -c`, включая исправление STARTTLS.
- Браузер: импорт Exchange, открытие мастера исправления, объединение одинаковых пулов, отказ при конфликте портов, отсутствие записи при просмотре плана, применение, сохранение DAG/исходных backend/таймаутов. Проверены отсутствие ошибок JavaScript и горизонтального переполнения на ширинах 1440, 390 и 320 px.
- Проверены синтаксис Python, JavaScript и install.sh, Docker Compose и сборка образа. Проверен запуск контейнера с read-only файловой системой, без внешней сети, на другом порту и с другим base_path.

Основной локальный прогон выполняется на Python 3.9. Проверки других версий Python и дистрибутивов заданы в CI; они не подменяются локальным результатом.

## Пределы результата

Это проверка указанных сценариев и совместимости, а не доказательство отсутствия любых ошибок. Работающие конфигурации серверов автоматически не заменялись. Для исправления реального 587 нужно заполнить адреса/порты и применить рассмотренный план в панели. Внешние NAT/DNS/firewall и фактические подключения Outlook/почтовых клиентов к рабочим Exchange в этой проверке не изменялись и не проверялись.

Неподдерживаемые сложные правила сохраняются с предупреждениями. Служебные ID/контрольные суммы блоков необходимы для целостности; удалять их из файла нельзя.
