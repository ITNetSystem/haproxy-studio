# Единый редактор импортированного Exchange

Начиная с 0.17, связанные импортированные службы показываются одной карточкой Exchange. Повторный импорт или применение нового конфига для появления карточки не нужны: достаточно обновить Studio и страницу браузера. Открытие списка не меняет конфигурацию HAProxy.

## Что находится внутри

Нажмите **«Изменить Exchange»**. В одном редакторе доступны OWA, Autodiscover, MAPI, ActiveSync, EWS, RPC, ECP и OAB — те службы, которые присутствуют в исходном конфиге.

Для каждой службы показаны её фактические домены, состояние, backend, условия путей, включение, балансировка, таймаут, HTTP-проверка и настройки серверов. Неизвестные параметры, исходные ограничения доступа, SNI, cookie и дополнительные проверки сохраняются. Редактор не создаёт отсутствующие службы и не применяет к импортированному ECP стандартный запрет из шаблона нового Exchange.

Общий список доменов вверху — объединение доменов всех служб. Чтобы заменить домены каждой службы этим списком, нажмите **«Использовать эти домены для всех служб»**. Без этого действия различия между OWA и Autodiscover сохраняются. При разных дополнительных ACL выберите существующий домен как образец в настройках соответствующей службы.

Все изменения отправляются одной кнопкой **«Проверить все изменения Exchange»**. Studio создаёт один черновик с общей разницей, проверяет весь конфиг и применяет его одним обычным reload с резервной копией и откатом при ошибке. Ошибка в одной службе не записывает частично подготовленные изменения остальных служб.

Для изменения параметров общего backend требуется подтверждение в его настройках. Изменение действует на все использующие этот backend маршруты, в том числе ручные и принадлежащие другим публикациям. Различающиеся правки одного общего пула отклоняются.

## Как определяется семейство

Публикации должны быть распознаны как Exchange и использовать сохранённые ACL/backend. Семейства `exch_<служба>_<группа>` и `be_exchange_<группа>_<служба>` объединяются в пределах одного frontend, TLS-режима и входа. Домены разных служб одного семейства могут различаться. При неизвестных именах объединение допускается только при точном совпадении доменов и адресов серверов. Неоднозначные повторяющиеся службы остаются отдельными.

Настоящий сервис Exchange, созданный обычным мастером, продолжает работать в своём редакторе. Почтовые SMTP/IMAP-публикации, другие приложения и сама Studio в группы веб-служб Exchange не входят.

Группа — единая точка управления существующими публикациями. В конфиге сохраняются служебные записи её участников, отдельные backend и исходный порядок маршрутов. Это позволяет сохранить разные проверки и таймауты. Экспортированный конфиг продолжает содержать эти записи и открывается после повторной загрузки без преобразования пулов.

## Выключение и удаление

На общей карточке можно включить/выключить все службы или удалить их управляемые маршруты одним проверяемым действием. Внутри редактора можно выключать службы по отдельности. Общие пулы, отдельные редиректы, `default_backend` и другие исходные правила остаются в конфиге и могут продолжать обслуживать запросы; выключение группы не является гарантией полного запрета доступа к Exchange.

Сертификаты и политики общего TLS-входа управляются как раньше: этот редактор не заменяет общий frontend шаблонными настройками. Защита публикации самой Studio остаётся активной.
