# Аккаунты, сертификаты и ручные backend

## Пароль и пользователи

В **Мой аккаунт** введите текущий пароль, новый пароль и повтор нового. Минимум — 12 символов. Другие сеансы аккаунта завершаются; текущий остаётся открытым. Начальный пароль в `state_dir/initial-password` после смены через веб не обновляется: это файл первоначальной выдачи, а не хранилище актуального пароля.

Раздел **Пользователи** доступен администраторам. Создайте аккаунт с ролью:

- **Администратор** — управление HAProxy, сертификатами и пользователями.
- **Только просмотр** — просмотр данных и смена своего пароля.

Можно изменить роль, сбросить пароль другого пользователя, отключить или удалить его аккаунт. Такие действия завершают его сеансы. Нельзя удалить себя, отключить свой аккаунт или лишить себя административных прав. В системе должен остаться включённый администратор. Для своего пароля используйте «Мой аккаунт».

При обновлении старый `admin` автоматически переносится из `auth.json` в приватный `users.json` без изменения пароля. Новая база становится источником авторизации; старый файл не предоставляет обходной вход. Хеши и файлы блокировок находятся в `state_dir` вне репозитория. Сохраняйте всю эту директорию при переносе или резервном копировании. Аварийное восстановление: остановить панель, выполнить `STUDIO_CONFIG=/etc/haproxy-studio/config.json python3 -m haproxy_studio --reset-password` из `/opt/haproxy-studio`, затем запустить службу. Новый пароль `admin` будет в `state_dir/initial-password`; другие аккаунты сохранятся.

## Сертификаты

Основной заголовок — ваше название. Случайное имя PEM показывается отдельно как технический файл и не меняется при переименовании: существующие пути в HAProxy сохраняются. Кнопка **Переименовать** меняет название в панели и списках выбора сертификата.

Удаление доступно для неиспользуемых PEM. Панель проверяет основную конфигурацию и `conf.d`, прямые пути `crt`, каталоги сертификатов, `crt-list`, ссылки на CA/CRL/DH-файлы и сохранённые настройки сервисов, включая выключенные. Если сертификат используется, сначала выберите другой и примените изменения соответствующего сервиса или TLS-входа. Неизвестные или нечитаемые зависимости требуют ручной проверки. Символьные ссылки через панель не удаляются.

Перед удалением приватная копия сохраняется в `state_dir/deleted-certificates/<id>/`. Она не появляется в Git и доступна администратору сервера для ручного восстановления. Удаление сертификата само по себе не перезагружает HAProxy.

## Ручные backend

В **Маршруты и серверы → Управление backend-пулами** показаны пулы из основного файла и дополнительных `*.cfg`. Для ручного пула нажмите **Удалить**. Если он используется в `use_backend` или `default_backend`, выберите пул замены либо явно отметьте удаление связанных правил. Затем просмотрите разницу, результат проверки HAProxy и нажмите **Применить изменения**.

Пулы мастера удаляются вместе с соответствующим сервисом. Backend самой панели защищён. При динамическом выборе backend или ссылках из служебных блоков панель требует ручного изменения конфигурации. Дополнительные зависимости проверяются реальным HAProxy перед применением.

Панель сохраняет копию основного файла и `conf.d`, повторно проверяет ревизию и синтаксис, записывает изменения и перезагружает HAProxy. При неудаче восстанавливает все изменённые файлы и выполняет восстановительную перезагрузку. История позволяет проверить восстановление файлов `conf.d`, существующих в текущей установке и выбранной копии. Новые дополнительные файлы автоматически не удаляются.
