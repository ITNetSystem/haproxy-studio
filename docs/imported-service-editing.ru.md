# Изменение импортированных сервисов

Начиная с 0.15, в **Сервисы → Изменить → Адреса и защита** у публикаций с импортированными ACL показаны настройки исходного backend, а не только домены. Обновление панели не требует повторного импорта.

Распознанный тип Exchange не применяет стандартный шаблон поверх рабочего конфига. Например, `/ecp` не становится автоматически закрытым, а отдельные backend OWA и ActiveSync не объединяются. Редактор показывает фактически заданные параметры.

## Что можно изменить

- Домены и образец правил для добавленных доменов.
- Пути в простых ACL `path`, `path_beg`, `path_end`, включая нечувствительное к регистру сравнение. Для этой публикации создаётся отдельный ACL; исходный ACL других публикаций сохраняется. Отрицания и остальные условия остаются прежними. Это изменение существующего условия, а не создание нового маршрута службы Exchange.
- Алгоритм балансировки и `timeout server` общего backend.
- Метод GET/HEAD/OPTIONS и путь простой HTTP-проверки, ожидаемый HTTP-код.
- Адрес и порт существующего сервера, вес, резервность, `maxconn`.
- Параметры `check`, `inter`, `rise`, `fall`.
- Явный `ssl` и `verify` внутреннего сервера.

Пустое поле означает отсутствие отдельной директивы: продолжают действовать `defaults`, `default-server`, `global` и настройки HAProxy. Например, `500ms` сохраняется именно как `500ms`; без единицы измерения HAProxy понимает время в миллисекундах. Переключатели `check`, `backup`, `ssl` отражают явные параметры строки `server`. Снятие переключателя удаляет этот параметр, но не отменяет наследование из `default-server`.

## Как применить

1. Откройте публикацию, нажмите «Продолжить» и измените нужные параметры.
2. Если меняете общий backend, отметьте подтверждение его изменения для всех использующих пул публикаций. Список перенесённых публикаций показан рядом. Изменение действует также на ручные маршруты и `default_backend`, которые ссылаются на этот пул, включая выключенные публикации после их включения.
3. Перейдите к проверке. Проверьте полную разницу конфига и результат `haproxy -c`.
4. Подтвердите применение. Studio сохранит резервную копию и выполнит обычный reload с проверкой и откатом при ошибке.

Изменение только названия типа, как и раньше, сохраняется без reload. Простое открытие и сохранение формы без изменений не меняет конфиг.

## Сохранение сложных настроек

SNI, cookie, `check-port`, `slowstart`, PROXY protocol и другие параметры не заменяются шаблонными значениями. Число и имена серверов этого редактора сохраняются. Сложные или неоднозначные строки серверов и многошаговые HTTP-проверки помечаются и остаются без изменений; остальные доступные поля пула можно редактировать.

Сертификаты общего frontend, TLS-режим входа, общий HTTP → HTTPS, отдельные правила редиректов и запрета доступа продолжают управляться настройками сертификатов и конфигурацией frontend. Они не подменяются значениями мастера нового сервиса. Это ограничение редактора импортированных публикаций: полного преобразования произвольного конфига в шаблон Exchange пока нет.
