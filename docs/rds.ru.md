# RDS через Connection Broker

В **Сервисы → Добавить сервис → Тип сервиса** выберите **RDS через Connection Broker**. Шаблон использует TCP/3389, нативный RDP без TLS-терминации, проверку TCP, балансировку leastconn и таймаут 8 часов. Внешний и внутренние порты можно изменить. Уже занятый порт RDP потребует другого внешнего порта или отдельного IP.

На шаге «Адреса и защита» выберите схему.

## На RDP-вход брокера / redirector

Укажите IP или DNS-имя сервера, который принимает начальное RDP-подключение к ферме, и его порт. Несколько входных серверов можно распределять и отмечать резервными. Это должен быть действительно работающий RDP-вход / redirector развёртывания: наличие одной роли Connection Broker не гарантирует, что этот сервер принимает клиентские подключения нужной коллекции.

HAProxy передаёт RDP без изменения и сохраняет данные выбора коллекции. Если брокер перенаправляет клиента на внутренний IP Session Host, клиенту нужен сетевой доступ к этому адресу, например через VPN. Один проброс брокера не делает остальные внутренние адреса доступными. Для доступа извне без такого маршрута используйте RD Gateway либо следующую схему.

## На Session Host по токену брокера (msts)

В Windows RDS настройте **token redirection**, отключив **IP address redirection**. Это настройка вашего RDS-развёртывания, панель её не меняет. В пул добавьте реальные IPv4-адреса и RDP-порты **всех** серверов назначения, на которые брокер может направлять клиентов. DNS-имена и IPv6 в этом режиме не принимаются, чтобы список явно соответствовал IPv4-адресам в токенах. При NAT должны совпадать адреса и порты в токене и пуле; преобразование токена панель не выполняет.

Мастер создаёт ожидание начального RDP cookie до 5 секунд и `persist rdp-cookie` в TCP backend. Распознанный токен `msts` направляет запрос на соответствующий доступный сервер из настроенного пула. Первое подключение без токена или с неизвестным токеном распределяется выбранным алгоритмом, по умолчанию leastconn. Начальные серверы должны участвовать в RDS-развёртывании и уметь обращаться к Connection Broker. Не заменяйте роль брокера простой балансировкой независимых терминальных серверов.

## Клиент и проверка

Используйте RDP-файл нужной коллекции из RD Web: он содержит параметры выбора коллекции, в том числе `loadbalanceinfo`. Адрес подключения/DNS должен вести на опубликованный вход HAProxy и выбранный внешний порт. HAProxy сохраняет `loadbalanceinfo`, но не выпускает и не переподписывает RDP-файлы и не конфигурирует коллекции, лицензирование, NLA или сертификаты Windows.

Проверка в панели подтверждает TCP-доступность, а проверка конфигурации — корректность HAProxy. После публикации отдельно проверьте реальный вход в нужную коллекцию, перенаправление брокером и повторный вход в существующий сеанс. Автоматические тесты проекта проверяют маршрутизацию синтетических RDP-токенов через настоящий HAProxy; полноценное развёртывание Windows RDS в тестах не запускается.

Дополнительный TLS и PROXY protocol для этого шаблона запрещены: RDP согласует безопасность самостоятельно. Публикация передаёт TCP, UDP-транспорт RDP не настраивается. Ограничение IP клиентов доступно в дополнительных настройках. RD Gateway по HTTPS — отдельная роль и этим шаблоном не создаётся.
