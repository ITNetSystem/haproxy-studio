# Понятные имена в haproxy.cfg

Начиная с HAProxy Studio 0.9, новые публикации и вновь импортируемые правила используют понятные **технические имена в самом конфиге**, а не только подписи в интерфейсе.

Например:

```haproxy
backend be_website
    mode http
    server web01 192.0.2.10:80 check
```

Это фрагмент, показывающий имена. Остальные параметры публикации задаются в мастере.

## Новые сервисы

На шаге **Адреса и защита → Имена в конфигурации** выберите **Понятные имена**. Этот режим включён по умолчанию для новых публикаций.

- **Имя основного backend** можно задать самостоятельно, например `be_website` или `be_exchange`. Пустое поле формируется из названия сервиса: «Почта компании» → `be_pochta_kompanii`.
- В строке внутреннего сервера задайте **Имя сервера в конфиге**, например `web01`, `exch01` или `studio_app`. Пустое поле формируется из адреса и порта: `192.0.2.10:443` → `srv_192_0_2_10_443`.
- Для отдельных путей задаётся **Имя backend этого пути**. По умолчанию получается, например, `be_exchange__owa`, `be_exchange__mapi`, `be_exchange__autodiscover`.

Используются латинские буквы, цифры, `_`, точка и дефис; первый символ — буква, максимальная длина — 63 символа. Русские названия сервиса автоматически транслитерируются. Имена backend должны быть уникальны во всех сервисах и ручных секциях, включая дополнительные `.cfg`; имена серверов — внутри их пула.

Сохранённые технические имена остаются стабильными при изменении отображаемого названия сервиса. Чтобы переименовать сам backend или сервер, измените соответствующее поле. Очистка поля в режиме понятных имён заново формирует имя автоматически. Для унаследованных пулов путей используются имена серверов основного пула; для отдельных пулов сохраняются заданные имена или формируются имена из адресов.

При импорте исходные имена серверов сохраняются, если соответствуют допустимому формату. Для неразличимых автоматически сформированных имён внутри пула добавляется порядковый суффикс.

## Существующие studio_be_… и node1

Обычная установка обновления **не переименовывает** работающие публикации автоматически.

1. Обновите панель до 0.19 и откройте **Сервисы**.
2. Нажмите **Понятные имена в конфиге**.
3. Просмотрите список `старое имя → новое имя` и полную разницу конфигурации. Имена серверов также изменятся на понятные.
4. Убедитесь, что внешние средства, использующие старые имена, учтены.
5. После успешной проверки HAProxy нажмите **Применить изменения**. Панель сохранит резервную копию и выполнит плавную перезагрузку HAProxy.

Одноимённым автоматически переименовываемым backend добавляются суффиксы `_2`, `_3` без случайных хешей. Уже настроенные понятные имена повторно не меняются.

Переименование обновляет `use_backend` и `default_backend`, сгенерированные мастером, и простые ручные ссылки в основном файле. Если ссылка находится в дополнительном `.cfg`, обнаружен динамический выбор через map или другая нераспознанная ссылка, операция останавливается с пояснением. Такие зависимости нужно согласовать отдельно. Доступ в режиме наблюдения и у аккаунта только для просмотра не разрешает переименование.

Адреса, порты, маршруты, проверки, балансировка и значения cookie сохраняются. При этом **внешние скрипты, сборщики метрик, команды Runtime API, track-ссылки и server-state могут использовать старые имена**. Studio не изменяет внешние файлы и скрипты; после переименования их нужно проверить и при необходимости обновить. История и состояния, привязанные к старым именам, могут не сопоставиться с новыми.

## Имена ACL с версии 0.19

Для новых публикаций и импорта префикс формируется из имени сервиса либо исходного backend. Например:

```haproxy
acl acl_exchange_pmir_owa_host hdr(host),lower,field(1,:) -i mail.example.ru autodiscover.example.ru
use_backend be_exchange_pmir_owa if acl_exchange_pmir_owa_host owa
```

Исходный ACL пути `owa` сохраняется. У новых правил мастера путь обозначается, например, `acl_exchange_path_owa`. Для дополнительных ветвей используются суффиксы `_rule_2`, для альтернативных наборов доменов — `_host_2`. При совпадении имён добавляется порядковый суффикс. Отображаемое название сервиса можно менять без переименования уже сохранённого ACL.

Действие **Понятные имена в конфиге** теперь включает ACL, в том числе у импортированных сервисов с общими backend. Исходные общие пулы сохраняются. Если ручное правило вне управляемого блока использует старый ACL, операция остановится с указанием зависимости: такую ссылку нужно согласовать отдельно. Обычное редактирование старого сервиса сохраняет старые имена.

## Имена файлов сертификатов

При новой загрузке имя PEM формируется из поля «Название»: `mail.example.ru` → `mail.example.ru.pem`, «Почта компании» → `pochta_kompanii.pem`. Точки и дефисы сохраняются, пробелы и служебные символы заменяются, пути в названии не принимаются как путь к файлу. Если другое содержимое уже занимает имя, используется `mail.example.ru-2.pem`. Существующий файл не перезаписывается; повторная загрузка тех же байтов возвращает уже сохранённый PEM.

Для старого случайного имени откройте **Сертификаты → Переименовать**, задайте название и выберите **Также дать PEM-файлу понятное имя**. Панель покажет разницу конфигурации и проверит её. Только после применения создаётся новый файл с правами `0600`, меняются прямые ссылки в основном и настроенных дополнительных `.cfg`, сохранённые модели сервисов и исходные TLS-bind для отката сервисов. При ошибке reload конфигурация откатывается. Старый PEM остаётся на месте для резервных копий; после проверки его можно удалить через панель, если он больше нигде не используется.

Если сертификат загружается через каталог `crt` или `crt-list`, автоматическое переименование файла блокируется: доступны изменение подписи без переименования и отдельная ручная миграция этих зависимостей. Ссылки во внешних скриптах и файлах вне настроенных конфигураций не переписываются.

## Ручная работа с конфигурацией

Понятные имена удобны для чтения конфигурации и ручных ссылок из других секций, например `use_backend be_website`. Управляемые блоки Studio по-прежнему содержат служебные идентификаторы и контрольные суммы. Для сохранения совместимости с мастером меняйте имена внутри этих блоков через поля панели: произвольная правка сгенерированного блока вручную нарушит проверку целостности. Служебные комментарии не нужно удалять или переименовывать.

Внутренние идентификаторы блоков остаются стабильными. С версии 0.19 новые ACL получают понятные имена, а старые переименовываются только через проверяемую операцию выше. В разделе **Маршруты и серверы → Технические детали** доступны фактические технические имена из текущего конфига.

## Обновление панели

В каталоге клонированного репозитория на сервере:

```bash
git pull --ff-only
sudo sh scripts/install.sh
sudo systemctl restart haproxy-studio
```

Обновите браузер через Ctrl+F5. Само обновление перезапускает только панель; переименование и плавная перезагрузка HAProxy выполняются отдельно после подтверждения плана.
