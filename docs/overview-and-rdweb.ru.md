# Обзор серверов и интерфейсы RD Web: 0.18

## Обзор без повторяющихся путей

В таблице «Доступность серверов» одна строка соответствует паре **сервис + адрес внутреннего сервера**. Например, проверки `/owa`, `/mapi` и `/ews` одной публикации Exchange не занимают отдельные строки. Импортированные службы из единой группы Exchange также объединяются.

Число активных соединений суммируется по соответствующим строкам HAProxy. В раскрывающемся разделе «Проверки служб» остаются состояние, путь, результат проверки, соединения и технические имена каждого backend/server. Частичный отказ не показывается как UP. При отсутствии части runtime-данных это явно отмечается; неизвестные счётчики не заменяются нулями.

Разные сервисы с одинаковым адресом не объединяются между собой. Несколько разных адресов одного сервиса остаются отдельными строками. Ручные и динамические назначения, для которых невозможно установить владельца или адрес, не объединяются по предположению. Исходные runtime-строки по-прежнему доступны API и используются в разделе маршрутов.

Обновление меняет отображение обзора, а не конфигурацию HAProxy. Перепубликовывать сервисы не нужно.

## RD Web и HTML5 на одном сервере

Раньше выбор обычного RD Web или HTML5 задавал только стартовую страницу корня. Второй интерфейс IIS оставался доступен по прямому пути. Это поведение сохраняется у существующих публикаций.

В мастере **«RDS: RD Web — редирект на HAProxy»**, где TLS завершается на HAProxy, теперь есть отдельное поле **«Доступные интерфейсы RD Web»**:

| Режим | Стартовая страница | Ограничение |
|---|---|---|
| Оба интерфейса — по умолчанию | Выбранный RD Web или HTML5 | Второй интерфейс также доступен |
| Только обычный RD Web | `/RDWeb/` | `/RDWeb/webclient` и подпути получают 403 |
| Только HTML5 | `/RDWeb/webclient/` | `/RDWeb/Pages` и подпути получают 403; `/RDWeb/` направляется к HTML5 |

Режим «Оба» позволяет независимо выбрать стартовую страницу. В ограниченном режиме стартовая страница выбирается согласованно с разрешённым интерфейсом.

Фильтр учитывает регистр и URL-кодирование. Неоднозначные кодирования, обратные и двойные слеши, управляющие символы и обходы через `..` в ограниченных режимах отклоняются. Правила действуют и при настроенных HTTP-исключениях. Общие `/RDWeb/Feed`, RPC и Gateway-пути не запрещаются этим фильтром.

Это ограничение стандартных HTTP-путей, а не замена авторизации Windows или гарантия запрета всех альтернативных IIS URL/rewrite-правил. Для HTML5-only блокируется весь `/RDWeb/Pages`, включая находящиеся там страницы входа или смены пароля. Если ваша схема SSO/аутентификации использует эти страницы, такой режим может не подойти: проверьте вход, SSO, смену пароля и подключение к опубликованному ресурсу перед использованием. В мастере и предварительном просмотре это ограничение указано явно.

В шаблонах **RD Gateway** и **RD Web со сквозным TLS** HAProxy не видит HTTP-пути и не может разделить интерфейсы этим способом. Выбор страницы там остаётся только выбором адреса открытия. Ограничение нужно настраивать в IIS либо использовать осознанно настроенную TLS-терминацию; транспорт существующей публикации автоматически не меняется.

Официальные инструкции Microsoft описывают [HTML5 web client и его URL](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/clients/remote-desktop-web-client-admin) и [обычный RD Web с каталогом Pages](https://learn.microsoft.com/en-us/troubleshoot/windows-server/remote/remote-desktop-web-access-troubleshooting).

## Проверка

Добавлены проверки объединения строк обзора, частичного отказа и отсутствующих данных, раздельного отображения разных сервисов. Режимы RD Web проверяются настоящими локальными HTTP/TLS-запросами, включая прямые и кодированные пути, HTTP-исключения и сохранение общих Feed/RPC-путей. Синтаксис проверяется матрицей HAProxy 2.4–3.4. Проверка на стенде не является проверкой конкретной Windows-схемы авторизации.
