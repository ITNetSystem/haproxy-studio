# Публикация сервисов без синтаксиса HAProxy

В разделе «Сервисы» нажмите «Добавить сервис». Мастер состоит из трёх шагов:

1. Название и тип сервиса. Шаблон подставляет обычные порты и режим передачи.
2. Внешний адрес, внутренние серверы и шифрование. Для сайта укажите домен и при необходимости путь. Укажите IP внутреннего сервера и порт уже работающего приложения. Для HTTPS выберите сертификат или загрузите новый.
3. Проверьте схему, проверьте TCP-доступность серверов и при необходимости задайте дополнительные настройки. Нажмите «Проверить и опубликовать», прочитайте результат проверки и подтвердите применение.

Панель проверит конфликт портов и маршрутов, запустит проверку установленного HAProxy, сохранит резервную копию и выполнит настроенную перезагрузку. Если runtime API был доступен, публикация дополнительно проверяет появление нового процесса HAProxy. При неудаче восстанавливается предыдущий файл. История и редактор сохраняют совместимость с публикациями из мастера.

## Шаблоны

| Сервис | Внешний порт по умолчанию | Режим |
|---|---:|---|
| Сайт HTTPS, WebSocket | 443 | Сертификат на HAProxy, HTTP или TLS до сервера |
| Сайт HTTP | 80 | HTTP |
| RDP | 3389 | Прозрачный TCP, нативная защита на сервере Windows |
| RDS через Connection Broker | 3389 | RDP-вход брокера/redirector либо токенная маршрутизация msts; [инструкция](rds.ru.md) |
| SSH | 22 | Прозрачный SSH; если 22 занят SSH хоста, выберите другой внешний порт |
| SMTP | 25 | Прозрачный SMTP/STARTTLS |
| Отправка SMTP submission | 587 | Прозрачный SMTP/STARTTLS |
| SMTPS | 465 | Сквозной TLS либо сертификат на HAProxy |
| IMAP | 143 | Прозрачный IMAP/STARTTLS |
| IMAPS | 993 | Сквозной TLS либо сертификат на HAProxy |
| POP3 | 110 | Прозрачный POP3/STARTTLS |
| POP3S | 995 | Сквозной TLS либо сертификат на HAProxy |
| ManageSieve | 4190 | Прозрачный протокол/STARTTLS |
| MySQL | 3306 | Нативный TCP |
| PostgreSQL | 5432 | Нативный TCP с сохранением согласования TLS |
| Redis | 6379 | TCP |
| Другой TCP | 8080 | Прозрачный TCP |
| Другой TLS | 8443 | Сквозной TLS либо сертификат на HAProxy |

Любой внешний и внутренний порт можно изменить. Для RDP, SSH, SMTP, IMAP, POP3 и PostgreSQL нельзя подменять нативное согласование безопасности обычной TLS-терминацией: мастер ограничивает несовместимые режимы. Для SMTPS/IMAPS/POP3S при выборе TLS-терминации обычный внутренний порт автоматически меняется на 25/143/110, если пользователь ещё не заменил его. Политика relay, пароли почты и учётные записи остаются на почтовом сервере.

## Сертификаты

Поддерживаются PEM/CRT с цепочкой и отдельным KEY, объединённый PEM, а также PFX/P12 с паролем. Лимит каждого файла — 512 КБ. Мастер проверяет дату действия, соответствие ключа и сертификата, а при публикации сайта — покрытие домена. Новый PEM получает случайное имя и права 0600; существующие сертификаты не перезаписываются. Ключ и пароль импорта не возвращаются в API и не попадают в журнал. Используется установленный OpenSSL. Автоматическая выдача и продление ACME в эту версию не входят.

## Дополнительные настройки

Можно выбрать несколько внутренних серверов, веса и резервные узлы; балансировку по очереди, по числу соединений или по IP; TCP- и HTTP-проверки с отдельной страницей; таймаут, интервал проверок и лимит соединений; разрешённые IP/CIDR клиентов; TLS до внутреннего сервера с проверкой сертификата и SNI; подмену Host, удаление префикса пути, HSTS и PROXY protocol v2. Проверка TLS включена по умолчанию при включении TLS к серверу; CA определяется для Debian/Ubuntu и RHEL-подобных систем, либо задаётся через ca_bundle.

PROXY protocol включайте только если внутренний сервер его поддерживает. Для RDP, SSH и баз данных доступно ограничение источников по IP. Проверка TCP подтверждает соединение с портом, а не готовность приложения или правильность пароля.

## Существующие публикации и изменения

Мастер может добавлять новые веб-домены к совместимому HTTP/TLS-входу, не занимая второй раз тот же порт. Префикс пути может расширять существующий домен; его приоритет показывается перед применением. Полная замена домена, уже занятого ручными правилами, блокируется. Несовместимый TCP/TLS-вход, занятый системный порт и пересекающиеся управляемые маршруты отклоняются.

Сервисы из мастера можно изменять, выключать, включать и удалять. Удаление убирает только их публикацию; внутренний сервер и сертификат остаются. В конфиге хранятся проверяемые служебные блоки и описание выбранных полей. Их ручное изменение блокирует последующее использование мастера до восстановления целостности. Дополнительные .cfg участвуют в обнаружении конфликтов и проверке, но мастер редактирует только основной файл.

## Что остаётся вне панели

DNS должен указывать на публичный адрес HAProxy, внутреннее приложение должно быть запущено, внешний TCP-порт должен быть разрешён в firewall/маршрутизаторе и у провайдера. Мастер не меняет DNS у регистратора, облачные сетевые правила и не устанавливает внутренние приложения. Общий UDP, QUIC/HTTP3 и произвольные директивы HAProxy этим мастером не генерируются; сложные ручные сценарии остаются в редакторе. Docker-вариант по-прежнему работает только в режиме наблюдения; публикация и загрузка ключей требуют нативной установки с нужными правами.

Расширенные группы доменов, Exchange и SNI описаны в [отдельной инструкции](exchange-sni.ru.md).
