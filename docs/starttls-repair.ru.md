# Исправление старых входов SMTP/587 и IMAP/143

Два IP в пуле Exchange могут быть узлами одной DAG. Дополнительные домены такой организации используют этот же пул. Мастер сохраняет узлы вместе и объединяет исходные пулы, отличающиеся только именами backend/серверов, если адреса и остальные параметры совпадают.

На обычном входе SMTP/587 или IMAP/143 нельзя выбирать Exchange через `ssl_fc_sni`: сначала начинается почтовый протокол, а переход на TLS происходит позже. Если весь вход обслуживает одну DAG, достаточно одного TCP-пула. Разные независимые DAG требуют однозначного назначения входящих соединений — например, разных IP на HAProxy или разных портов. DNS-имя само по себе в начале такого TCP-соединения не передаётся.

## Через веб-интерфейс

1. Обновите Studio до 0.22. Откройте **Сервисы → Исправить SMTP / 587**. Эта кнопка также доступна рядом с предупреждением старой службы внутри Exchange.
2. Проверьте все показанные пулы / DAG. Исправляется **весь исходный вход**, а не только карточка, из которой открыто окно. Список построен из текущего конфига.
3. Укажите **IP на самом сервере HAProxy** и входящий порт для каждой строки. Это адрес привязки `bind`, а не IP Exchange и не адрес внешнего NAT. `*` означает все IPv4-адреса сервера. На одном IP разным назначениям нужны разные порты. При разных IP можно оставить порт 587 каждому.
4. Адрес прежнего входа подставляется только для старого backend по умолчанию. Адреса остальных назначений остаются пустыми: Studio не назначает их догадкой. При NAT отдельно сопоставьте публичные подключения этим адресам/портам на HAProxy.
5. Нажмите **Проверить план исправления**. Мастер проверит конфликты и выполнит `haproxy -c`. Просмотрите diff. До применения рабочие файлы не меняются.
6. После проверки нажмите **Применить изменения**. Сохраняется резервная копия и выполняется reload. При неудаче файлы восстанавливаются.

В результате старый frontend заменяется управляемыми TCP-службами без SNI. Они появляются внутри соответствующего Exchange при однозначном сопоставлении с DAG. Для нового порта 143/587 используется STARTTLS на Exchange, без немедленного TLS между HAProxy и почтовым сервером.

Исходные backend сохраняются, поскольку могут обслуживать SMTPS/465 и другие существующие публикации. Новые управляемые пулы независимы: последующее изменение их адресов не переписывает старые backend. Таймауты клиента и сервера сохраняются отдельно; журналирование и проверки переносятся в поддерживаемых вариантах. Обычная запись `check port 587` переносится, когда порт проверки совпадает с адресом сервера; другой порт проверки автоматически не удаляется.

## Что мастер не делает автоматически

- Не меняет DNS, firewall, NAT или сетевые адреса операционной системы.
- Не назначает незаданные адреса/порты и не переносит стандартный порт 587 между организациями без явного выбора.
- Не заменяет входы с неподдерживаемыми ACL, ограничениями доступа, нестандартным bind или другими неизвестными политиками. В таких случаях показывает причину и оставляет конфиг как есть.
- Не применяет конфиг, не прошедший проверку. Ошибки других секций и файлов сертификатов нужно исправлять отдельно.

Для IMAPS/993 и SMTPS/465, где TLS начинается сразу, по-прежнему доступна маршрутизация по SNI при его поддержке клиентом.

## Сообщение о конфликте `*:587`

Звёздочка относится к самому HAProxy, а не к серверам Exchange. Например, `*:587 → EV` и `*:587 → PMIR` занимают один и тот же вход. Мастер покажет названия обоих назначений до генерации конфига. Для одного IP задайте разные порты либо используйте разные локальные IP на HAProxy. Узлы одной DAG остаются в одной строке и не требуют отдельных входов.

Если нужен выбор по имени SNI, используйте IMAPS/993 или SMTPS/465 с TLS с начала соединения и заполните «Домены SNI» в мастере Exchange. Добавление текстового поля SNI к обычному 587/STARTTLS не сделает такую маршрутизацию рабочей.
