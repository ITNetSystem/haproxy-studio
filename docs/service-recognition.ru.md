# Распознавание сервисов — 0.14

Exchange — назначение приложения, HTTPS — способ подключения. Импорт сохранял транспорт HTTPS, поэтому раньше Exchange-публикации отображались как обычные сайты. Теперь назначение определяется отдельно и показывается в «Сервисах», результатах импорта и «Маршрутах и серверах».

## Уже импортированные публикации

После обновления приложения обновите страницу. Повторный импорт не требуется. Распознавание выполняется при чтении текущих настроек и не записывает изменения в конфигурацию HAProxy.

Для Exchange используются проверки вида `/owa/healthcheck.htm`, `/mapi/healthcheck.htm`, `/autodiscover/healthcheck.htm` и других служб, а также относящиеся к публикации маршруты. Признаки соседнего backend на общем frontend не переносятся на другие сервисы: например, OwnCloud рядом с Exchange останется сайтом HTTPS.

## Все типы мастера

| Тип | Основные признаки |
|---|---|
| Microsoft Exchange / Outlook | Характерные health checks; OWA, MAPI и сочетания путей служб Exchange |
| Сайт HTTP | HTTP-режим без TLS, когда конкретное приложение не определено |
| Сайт HTTPS | HTTP-режим с TLS, когда конкретное приложение не определено |
| WebSocket / веб-приложение | Явные Upgrade/WebSocket ACL и заголовки; имя как дополнительная подсказка |
| RDS: RD Gateway | Специфичный маршрут `/remoteDesktopGateway/`; в сквозном TLS — имя и HTTPS-порт как предположение |
| RDS: RD Web со сквозным TLS | Имя RD Web/webclient и HTTPS-порт как предположение; содержимое зашифрованного потока недоступно |
| RDS: RD Web с обработкой HTTP | `/RDWeb/` и `/RDWeb/webclient/` в маршрутах, проверках или адресе перенаправления |
| HAProxy Studio | Локальный адрес настроенной панели или её характерная API-проверка |
| RDS через брокер | Токен `msts`; RDP persistence и имя брокера дают дополнительную подсказку |
| RDP | Стандартный порт 3389, если роль брокера не подтверждена |
| SSH | Порт 22; проверка приветствия SSH |
| SMTP / STARTTLS | Порт 25, `smtpchk` или проверка EHLO |
| SMTP Submission / STARTTLS | Порт 587 и SMTP-проверки |
| SMTPS | Порт 465; SMTP за TLS с первого байта, включая терминацию с backend 25/587 |
| IMAP / STARTTLS | Порт 143 |
| IMAPS | Порт 993; TLS-обёртка перед IMAP |
| POP3 / STARTTLS | Порт 110 |
| POP3S | Порт 995; TLS-обёртка перед POP3 |
| ManageSieve / STARTTLS | Порт 4190 |
| MySQL | `mysql-check`, порт 3306 |
| PostgreSQL | `pgsql-check`, порт 5432 |
| Redis | `redis-check`, PING/PONG-проверки, порты 6379/6380 |
| Другой TCP-сервис | Общий TCP без достаточных признаков приложения |
| Другой TLS-сервис | Общий или сквозной TLS без достаточных признаков приложения |

Учитываются текущие порты backend, в том числе при нестандартном внешнем порте. Сохранённый конкретный тип публикации из мастера имеет приоритет. Стандартный порт или имя — подсказка, а не проверка работающего сервиса по сети.

На одном TCP/443 могут находиться HTTPS-сайт, Exchange, RD Gateway и другие приложения. Без подходящих дополнительных признаков такой поток остаётся общим TLS. Один маршрут RPC также не доказывает конкретную роль. Конфликтующие признаки портов отображаются как неоднозначные.

## Как уточнить тип

При импорте у каждой найденной публикации есть поле **«Тип сервиса»**: автоматически определённый тип и все варианты мастера.

У уже перенесённой публикации откройте **«Изменить» → первый шаг → «Тип сервиса»**. Там показана причина автоматического определения. Выберите назначение вручную либо оставьте автоматическое распознавание. Выбор сохраняется после предварительного просмотра и применения. Если изменён только тип, Studio записывает служебные метаданные с резервной копией, без перезагрузки HAProxy. Перед записью сервер повторно проверяет отсутствие изменений исполняемых правил. Чтобы вернуться к распознаванию, выберите «Автоматически».

Для импортированной публикации это уточнение назначения. Существующий транспорт, порты, TLS, ACL, health checks, общие пулы и ограничения сохраняются. Выбор Exchange не добавляет автоматически стандартные маршруты и запрет ECP из шаблона новой публикации. Для смены режима работы требуется отдельная проверяемая перенастройка.

Backend разных исходных служб Exchange сохраняются раздельно: уточнение типа не объединяет их и не копирует общие пулы.

## Проверки

Есть примеры автоматического распознавания для каждого из 24 типов мастера. Отдельно проверяются уже импортированный Exchange, стандартные и нестандартные порты, проверки протоколов, неоднозначный RPC/TLS, отсутствие влияния соседних маршрутов, ручной выбор и возврат к автоматическому определению.

Тесты сравнивают исполняемые строки HAProxy до и после уточнения назначения: меняются только служебные метаданные. Проверяется отсутствие записи при автоматическом распознавании.

С версии 0.15 параметры импортированного backend и простые ACL путей доступны в редакторе публикации: [как изменить импортированный сервис](imported-service-editing.ru.md).
